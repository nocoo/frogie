# 08 - MVP 实施

## 并行分工

主控负责接口、依赖、集成审查、完整检查和原子提交。Pi 根据行为契约独立编写测试，Grok 实现 Core、宿主及 Model／ViewModel，Agy 按 Basalt 3.0.0 发布模板组装纯 View。测试与实现分别拥有文件，根配置和 Git 操作由主控统一处理。

每项行为先确定输入输出与失败边界，测试取得有效红灯后实现；当前实现与下一项测试准备并行。测试预期依据需求维护，逻辑、测试和必要文档验证通过后一起提交。

## 交付顺序

1. 建立 workspace、版本锁定、严格 TypeScript、Biome、Vitest 和暂存快照门禁。
2. 从最小定义进入真实 Pi Harness，经 Dashboard 完成一次输入输出。
3. 扩展完整角色、Skills、脚本、Workflow 画布和 MD 编辑，交付 `zeppelin` seed。
4. 验证派发并行、沙箱、预算、取消、SQLite 恢复、原生上下文压缩和生命周期。
5. 完成从空白搭建 Squad 的浏览器路径及三模式隔离，以同一快照运行真实评估。

每阶段扩展已有可运行路径。确定性测试仅在模型边界使用替身，持久化、工具、文件和浏览器操作采用真实实现。

## 验收

非 View 生产逻辑的语句、分支、函数和行覆盖率分别至少 95%，类型、Biome lint 和格式检查保持零错误、零警告。纯展示 View 单独排除覆盖率，继续接受静态检查、E2E 和视觉验收。完整门禁及拒绝提交的证据按 [Tests](06-tests.md) 维护。

所有容器和交互控件遵循 Basalt 3.0.0 官方模板及发布组件；画布的专业交互由 React Flow 提供。实例建立、切换与释放遵循 [Dashboard](04-dashboard.md) 的生命周期约定。

完成证据包含可运行的本地 Dashboard、定义编辑与 Workflow 设计、seed 对话、真实并行、进程恢复、压缩后继续对话、L1 结果、完整 E2E 与真实模型评估。真实模型连接和预算明确授权，运行报告保存在隔离本地数据目录。
