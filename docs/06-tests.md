# 06 - Tests

## 验证目标

测试证明 Frogie 自己的定义、接入、权限和界面行为可靠；真实模型 Evaluation 证明定义能驱动 Pi Durable 完成工作。两类验证共用运行端、定义和产物协议，各自检查最适合自己的边界。

首期完整落实 6DQ L1，并为 MVP 增加少量必要的真实 Pi 集成和浏览器验收。每个用例对应一个具体风险，业务场景由 [Evals](07-evals.md) 集中维护。

## 6DQ 分工

| 维度 | 本项目的职责 | 首期执行方式 |
| --- | --- | --- |
| L1 | 单元测试、四项覆盖率、严格静态检查、提交拦截 | 每次提交检查 Git 暂存快照 |
| L2 | 模块与协议集成 | 用真实 Pi、SQLite 和受控进程验证少量关键边界 |
| L3 | 完整用户路径 | 从空工作区通过浏览器搭建完整 Squad，贯穿画布、绑定、调试与产物 |
| G2 | 安全检查 | 权限、路径、认证和沙箱风险先落实到对应测试；依赖与密钥扫描随推送门禁建设 |
| D1 | 测试数据与环境隔离 | 所有层次从首个用例开始执行 |

L1 是首期质量门槛，选定的 L2、L3 和真实评估是 MVP 的产品验收材料。6DQ 各维度按实际执行证据分别记录。

## 测试工具与目录

采用 Vitest 组织确定性测试，V8 提供覆盖率，Playwright 负责浏览器路径。模型使用 Pi `Models` 接口的可编程假实现，工具使用独立临时数据；集成测试保留真实 Pi Harness 和存储。

```text
packages/core/src/**/*.test.ts
apps/dashboard/src/**/*.test.ts
tests/
  fixtures/
    minimal-squad/
  integration/
  e2e/
seeds/
  seed.ts
  profiles.ts
  model-scenarios.ts
evals/
  ...
```

模块单元测试就近放置；跨模块、子进程和浏览器测试分别进入 `tests/integration/` 与 `tests/e2e/`。定义脚本与评估断言的确定性测试靠近其源码。`minimal-squad` 用于 L1／L2 与聚焦边界，完整搭建路径使用 `zeppelin`。

`seeds/` 统一提供空白初始化、样例引用与确定性模型场景。E2E 从受 Git 管理的定义和简报读取填写材料，持久化结果由真实界面操作产生。生成的数据库和报告位于本次 `data/e2e/<run-id>/`。

工程初始化时在根 `package.json` 提供单元测试及覆盖率、集成测试、浏览器测试、L1 和推送检查入口，精确命令同步到根 `AGENTS.md`。真实模型评估使用独立入口。

## L1：按风险覆盖行为

| 边界 | 主要断言 |
| --- | --- |
| 定义解析 | 字段、唯一主控、嵌套角色、Skill `name` 与目录、ID 与引用正确；重复键、断链、越界路径和符号链接被定位 |
| 工作流图 | 节点、入口、边、正文与角色引用一致；同角色多步骤和复核回路可解析；图与 MD 往返、执行指导渲染稳定 |
| 版本与编辑 | 文件或脚本改变影响摘要；顺序规范化稳定；外部修改触发保存冲突；候选无效或写入失败保持原文件与草稿 |
| 角色装配 | 默认值、角色值和获准微调正确；实际模型与思考等级可解析；子角色具有自己的明确配置 |
| 权限 | 工具、Workflow 与宿主授权取交集；直接子角色派发、Extension 选择与工具过滤正确；权限收回在新输入、模型与工具入口生效，重放沿用检查 |
| 模型连接 | provider、模型许可、思考等级与凭据引用可解析；环境授权明确；E2E 缺少虚构配置时失败，输出保持脱敏 |
| 公共协议 | Pi 状态原样映射；快照替换、重连、错误、分页和产物引用的归属检查正确 |
| 环境与 seed | 模式和绑定选择、实例固定、迟到结果丢弃、seed 确定性与重放拒绝、重置归属和自动测试锁定正确 |
| ViewModel | 图编辑与撤销、节点和角色草稿、校验、提交重试的 `requestId`、排队与停止、会话切换和断线恢复符合用户动作 |
| 宿主边界 | argv 构造、重放准入、输入限制、超时、输出上限、产物回执、清理归属和持久预算正确 |
| 脚本与评分 | 严格字段、有限数值、ID 唯一性、空分配、负余额与稳定顺序符合 Skill 契约；业务断言失败可以指向具体证据 |

相同规则以表驱动用例覆盖等价类。测试断言结果、错误和可观察副作用，辅助结构按真正需要复用。

预算测试集中验证原子准入：两个调用竞争最后一个额度时仅一个发送；预扣失败保持零发送；提交后、发送前中断保留消耗；相同 Task 的实际重试重新计数，`completeSimple` 内部复用 stream 只计一次。启动和快照读取保持计数，等待并发名额响应期限与取消，工具重放进入与脚本实际执行分别计数。

### 覆盖范围

覆盖率纳入 Core 运行代码、Dashboard 的 Model／ViewModel／服务端／运行端代码、seed 生成逻辑、Squad 可执行脚本和评估断言。纯展示 View、类型声明、生成物和第三方代码单独列明在配置中。

语句、分支、函数和行四项均达到 95%。报告保留公共包、Dashboard 与脚本／评估代码的归属；子进程执行证据由相应测试记录，父进程覆盖率只反映实际被插桩的代码。

完整检查入口执行全部必需用例，套件为空、存在跳过或 `.only`、接收聚焦筛选时检查失败。开发调试可单独运行文件或用例，结果标为局部反馈，完整门禁仍执行全量检查。模块导入成功和快照数量分别作为辅助信息，行为断言构成主要证据。

### 静态检查

TypeScript 启用 `strict` 并执行类型检查；JavaScript 脚本纳入对应的类型或语法检查。统一使用 Biome 的明确规则和只读格式检查，警告同样导致失败。

文档检查覆盖相对链接、索引完整性和约定格式；定义检查读取全部 Squad，校验文件、引用和脚本声明。模型服务连通性留给运行预检。

## L2：三个接入边界

### 1. 绑定、投递与观察

使用真实 Pi 和 MemoryStorage 加载最小 Squad，通过公共入口创建主控及两个同角色的独立会话。可编程模型按输入返回固定响应或工具调用。

在一条可追踪链路中检查：

- 角色装配、会话身份及有效工具范围。
- 相同 `requestId` 的重复投递取得同一 Submission。
- busy 时的 follow-up、steer 和 reject，以及排队撤回。
- 前台派发的子会话所有权、真实答复回传和向下取消。
- 观察者中途连接、断开和重新取得快照，状态与 Harness 当前值一致。

公共包的 `./testing` 导出 `registerRuntimeConformance({ createHost })`，由使用方在 Vitest 套件中调用。回调契约为：

- `createHost({ definition, binding, models, registry, storage, workDir }, context)` 接收测试提供的定义、绑定、确定性模型、工具注册表、独占 MemoryStorage 和临时资源根。
- 返回 `{ runtime, dispose }`，`runtime` 是 Core 的 `RuntimeHandle`；`dispose(context)` 有界关闭句柄与宿主拥有的资源，可重复调用。创建失败同样释放已接纳资源。
- 套件通过 `service` 执行行为并核对原生 `harness` 的已提交状态，在 `finally` 中释放宿主，再清理自己创建的目录。

Dashboard 的参考宿主和 `tests/integration/` 内直接使用 Core 的独立最小宿主运行同一组检查。最小宿主同时承载轻量 HTTP 适配验证，复用操作与观察结果断言，证明协议可独立接入。身份、版本或作用域不匹配分别形成稳定错误，观察首帧和后续帧与原生 `ConversationView` 一致。

### 2. SQLite 与进程恢复

使用 Node SQLite 原生适配器、独立数据库和真实子进程。控制器在明确的持久化边界等待信号，然后终止自己创建的 Harness 进程，再由新进程打开原存储。

围绕一次“父会话派发 → 子会话调用工具 → 回传结果”检查两个必要窗口：

| 中断点 | 必须成立的结果 |
| --- | --- |
| 子会话已创建且输入已接纳 | 恢复使用原 Conversation、Submission 与所有权关系 |
| 可重放工具已保存幂等回执，Pi tool result 尚未提交 | 工具重新进入后读取原回执，外部效果保持一次 |

同一恢复材料另检查默认 unsafe 工具的中断语义：出现 Pi 的 `interrupted` 结果，实际调用次数保持原值。缺失 Extension 或定义摘要不匹配的启动预检也在此边界验证。

断言读取数据库、任务记录、外部回执和最后答复；控制器按信号同步，有界等待。数据库所有权检查保证第二个宿主无法同时使用它。

使用 Pi 官方存储适配器时，Frogie 测试自己的接入与恢复契约。集成方编写自有 Storage 时，额外运行 Pi 提供的 `registerStorageConformance()`；自有 ExecutionEnv 使用对应的 `registerEnvConformance()`。

### 3. 本地宿主安全边界

对 HTTP 文件服务和实际 Docker 脚本执行器运行一组独立检查：未授权来源、错误会话归属、路径逃逸和保存冲突均保持边界；脚本能够读取指定输入，同时只能写自己的临时空间。

环境检查在测试自己的目录中建立不同模式与 Harness：切换后旧实例请求返回 `409`，切换前已接纳的写入仍只改变原数据库，新界面读取目标快照。重复 seed、错误归属、符号链接路径、跨范围产物和自动 E2E 越界切换分别返回诊断，其他存储保持原样。

独立运行端用例复用最小宿主，核对令牌、`runtimeId`、协议和作用域；错误身份、越权操作及重定向均在边界拒绝。Dashboard 切换或关闭后，独立宿主继续持有自己的进程和存储，浏览器与日志保持凭据脱敏。测试清理由创建该宿主的控制器完成。

沙箱用例使用虚构数据和哨兵文件，验证宿主私有文件、凭据和外部网络不可达，资源超限与取消能结束整个调用，其他环境和容器保持原样。测试记录实际容器参数与结果。

Docker 不可用时环境预检失败并说明原因。沙箱集成验收以真实执行证据为准，L1 的参数测试继续独立运行。

## L3：从零搭建完整 Squad

### 启动条件

Playwright 连接实际构建的 Dashboard、本地服务、Pi SQLite 和 Docker 沙箱。启动器创建独立目录，使用 `empty` seed；初始定义列表、Harness 绑定与会话历史为空。认证走正式的一次性启动凭据和本地会话流程。

唯一的模型替身位于 `Models` 边界，由已追踪的场景提供响应与工具调用。工具参数使用本次真实产物引用，后续响应读取实际工具结果；文件、绑定、会话、脚本与产物接口全部使用应用实现。虚构模型连接由启动器提供给正常的模型目录与配置界面。

### 主路径

`zeppelin` 的填写材料复用 [Squads](05-squads.md) 对应的定义源，运行简报复用 [Evals](07-evals.md) 的 E1。浏览器依次完成：

1. 从空状态新建 `zeppelin` Squad 与 `command` 主控角色，确认顶部切换器选中该 Squad，E2E 模式与锁定范围清晰可见。
2. 在技能界面创建四个 Skills，填写正文，通过脚本编辑入口建立 `resource-budget/calculate` 的声明与源文件。
3. 在角色界面创建其余八个角色，建立完整目录层级，为全部九个角色配置 Prompt、Skills、Tools、Scripts 与思考等级。保存后看到九个角色及有效引用。
4. 新建 `emergency-transit` Workflow，从角色面板实际拖入八个步骤，拖动节点并通过端口连出十条边，设置入口、交接说明与步骤正文。从节点打开对应 Role 编辑 Prompt 和能力，确认同角色的其他节点同步显示配置。
5. 保存画布，切换源码核对 MD，再在源码中修改一条交接说明并返回画布验证。刷新后核对节点、坐标、连线、角色归属和文件内容，确认它们来自已保存定义。
6. 通过界面冻结快照、新建环境和 Harness 绑定，选择测试模型连接，检查角色的最终模型、思考等级、权限与沙箱，再启动真实 Harness。模型连接属于环境配置，定义快照保留可用于真实模型的同一组文件。
7. 在 Chat 中新建以 `command` 为入口并绑定该 Workflow 的对话，提交 E1 简报并发送输入，观察主控到行动、工程与补给，以及行动到航行与战术的真实派发。展开子会话、脚本回执和 `plan.md`，核对沙箱计算与已保存产物。
8. 刷新页面重新进入同一 Squad／Harness，确认 `RuntimeScope`、Conversation、Submission 与产物摘要保持一致，历史从原 SQLite 读取。

完整搭建只执行这一条主路径。所有被验收的创建、编辑、连线、绑定和投递操作都由浏览器操作实际控件完成；测试控制器只准备空环境、提供填写材料并读取落盘结果作断言。模型请求、脚本回执与产物共同证明执行，八个步骤的画布图与 Pi 实际会话树分别核对。

桌面画布使用真实指针拖动和端口连接，等待界面状态或服务端持久化结果推进测试。断言同时检查 UI、MD、目录层级和绑定摘要，并确认仓库内的原始 `squads/` 保持原样。九角色定义全部校验，E1 执行其中六个角色的链路，其余角色由 E2 的真实评估验证。

### 主路径检查点

检查点位于同一条浏览器路径内，各项通过后继续下一阶段：

| 位置 | 必需断言 |
| --- | --- |
| 第 5 步后：定义落盘 | 九角色、四 Skills、脚本与八节点十连线齐全；目录、正文、坐标和引用可重新加载，保存定义摘要 |
| 第 6 步后：绑定启动 | 实际 `RuntimeScope` 与快照一致；角色模型、思考等级、工具授权及沙箱预检对应本次绑定 |
| 第 7 步后：执行交付 | Pi 保存真实父子所有权和答复；脚本回执、计算结果与 `plan.md` 通过 E1 的业务断言 |
| 第 8 步后：刷新恢复 | 原作用域、Conversation、Submission、定义及产物摘要保持一致，显示来自原存储 |

失败立即停止后续阶段，保留已取得的 trace、截图、定义和运行诊断，并标记未完成的检查点。完整通过后导出的快照与报告用于 MVP 真实评估；失败阶段的文件作为调试材料保留。

### 聚焦补充与证据

切换与交互使用小型独立用例，复用已校验样例以聚焦边界：

- 同一锁定 E2E 范围内切换 Squad／Harness，核对导航、草稿提示、会话与产物范围，以及旧响应和订阅的处理。
- 在测试拥有的临时工作区中切换 Local／E2E／Prod，核对数据库独立、重启保留、临时 E2E 释放、偏好保存和自动启动锁定。
- 验证输入法发送、源码保存冲突、失败重试、停止、焦点恢复，以及画布的键盘和触屏等价入口。

视觉验收使用实际发布的 Basalt 与 React Flow 包，在 390px、1440px、浅深主题和 reduced-motion 下检查布局与关键动作。完整创建过程集中在主路径，其他视口复用其定义检查适配与可访问性。

报告保存 Playwright trace、关键截图、生成的定义快照及摘要、`RuntimeScope`、Pi ID 与产物断言。生成快照保留在本次 `reports/`，供真实评估选用。测试结束后关闭拥有的进程与容器、释放临时工作区和存储，保留验收材料。

真实模型验收通过 Evals 的同一执行入口在独立 Local 环境进行，Dashboard 展示实际评估报告并可追溯证据。确定性 E2E 与真实模型结果分别记录，共同锁定 MVP 的完整路径。

## 门禁与隔离

Pre-commit 和 pre-push 以 [开发约定](02-repository-and-workflow.md) 为准。实现时保留一个只读检查入口，hooks 与 CI 调用它，检查对象分别为暂存快照和实际推送 SHA。

完整搭建 E2E 是 MVP 的必需 CI 验收项，执行实际待验证版本的构建产物；显式手动入口复用同一启动器、检查点和断言。套件缺失、跳过、聚焦筛选、空跑、失败或 Docker 等必需条件缺失均返回失败，报告记录执行版本、定义摘要和各检查点结果。

门禁在独立 Git fixture 中证明以下事实：健康快照可通过，测试失败、任一覆盖率不足、类型错误、lint 警告、缺工具、空报告和超时会拦截提交；未暂存修复无法掩盖暂存错误。执行结束后工作区、暂存区与无关进程保持原样。

每次测试生成唯一工作目录、环境 ID、数据库、端口与容器标签。浏览器测试的根位于 `data/e2e/<run-id>/`，启动器锁定自己的可编辑定义根与资源目录；环境变量按白名单提供虚构值，认证仍经过真实本地会话校验。自动测试保持日常 Local／Prod 目录和用户偏好原样，清理先核对所有权。

跨模式切换使用测试拥有的临时工作区，在其中分别创建标为 Local、E2E、Prod 的独立存储；该套件通过真实交互启动模式验证手动切换。自动 E2E 锁定由另一项断言覆盖，所有测试都只获得本次临时资源及模型替身。

常规 L1 的目标为 30 秒内，推送检查目标为 3 分钟内；实现后报告实际耗时和完整检查结果。真实模型评估由独立授权入口执行；完整沙箱验收提供独立命令，必需 E2E 使用同一沙箱实现，CI 提供对应 Docker 环境。

## TDD 与原子交付

按可运行的纵向能力组织实现，每一段同时交付执行入口与可操作界面：

| 顺序 | 最小可用能力 | 主要验证 |
| --- | --- | --- |
| 1 | 在空工作区创建最小 Squad，绑定本机 Harness 并完成一次输入输出 | 定义与配置 L1、真实 Pi 接入、浏览器主路径起点 |
| 2 | 创建角色与技能、通过画布编辑 Workflow 并落盘 MD | 图与编辑 L1、从零搭建路径扩展 |
| 3 | 派发、沙箱、产物、作用域切换、取消与 SQLite 恢复 | 权限与状态 L1、持久化及隔离 L2、完整搭建 E2E |
| 4 | 使用界面生成的同一份定义完成真实评估与报告闭环 | 评分 L1、必需 E2E、三个真实评估项和人工 UI 验收 |

每个行为先写预期失败的测试，再实现最小通过路径，最后整理；代码、相应测试与必要文档原子提交。报告区分执行过的测试、覆盖率、人工验收和真实模型结果，证据关联实际代码与定义版本。

## MVP 完成条件

L1 的全部检查通过并能拦截失败，关键 Pi 接入与进程恢复具有真实证据，从空状态搭建完整 `zeppelin` 的 E2E 在 CI 通过，全局切换与三模式隔离得到验证，脚本隔离经过实际执行，真实行为评估取得独立报告。问题由失败断言定位到定义、公共接入、宿主、界面或模型行为，供下一轮 TDD 修正。
