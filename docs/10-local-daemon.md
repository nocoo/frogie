# 10 - 本地 Daemon

## 职责

`apps/daemon/` 是 Frogie 的常驻本地宿主，统一管理项目、Squad 绑定、Pi Harness、SQLite、模型、工具、沙箱和出站连接。Dashboard 使用它的本地管理接口；远端 Gateway 使用 [通信 SDK](11-communication-sdk.md) 的受限接口。

daemon 的运行独立于浏览器、Dashboard 静态资源和远端连接。它监督各 Harness 工作进程，本身承担生命周期与路由，Agent 协作继续使用 [Core](03-core.md) 的 Pi 语义。

## 项目与绑定

| 对象 | 保存内容 |
| --- | --- |
| Project | 稳定 `projectId`、名称、Squad 来源、环境列表、启用状态和可选连接引用 |
| 环境 | `environmentId`、Local／E2E 模式、模型连接、预算、权限和定义选择 |
| Harness 绑定 | `RuntimeScope`、定义摘要、Pi 与扩展版本、实际配置、SQLite 身份 |
| Connector | 固定远端 origin、预期项目与环境身份、设备身份、凭据引用、获准作用域及能力 |

项目首先以本地对象成立，远端连接是可选配置。首期每个项目使用一个 Squad；同一环境内 Squad 与 Harness 一一对应。至少两个不同项目的 Squad 可同时运行，每个 Harness 有自己的主控根会话及子角色会话。

`RuntimeScope` 包含 `projectId`、`environmentId`、`squadId`、`harnessId`。存储、操作、缓存、回执和产物都核对完整作用域。模型配置、权限、历史与业务资源引用按项目隔离。

`deviceId` 标识本机 daemon 安装，`runtimeId` 标识一个 Harness 的持久运行绑定；两者重启保持原值。进程 PID、WebSocket 连接 generation 和订阅 epoch 只标识本次生命周期，不能替代存储身份。

每个数据根只有一个 daemon 所有者，每份 Harness SQLite 只有一个工作进程持有；Local 与各次 E2E 使用不同数据根和端口。一个项目失败、停止或额度耗尽只影响其作用域；共享模型连接的服务故障可以影响多个项目，界面按实际原因分别说明。

## 本地闭环与远端能力

| 行为 | 无远端连接时 |
| --- | --- |
| 查看和编辑角色、Skills、Workflow | 使用本地定义，正常工作 |
| 主控或指定 Role 聊天、派发 | 使用本地模型连接、定义和历史；按当前可用工具执行 |
| 查看历史、搜索会话、总结历史 | 从本机 SQLite 与产物读取；总结使用获准模型 |
| 调试 Skill 与脚本 | 使用明确输入、独立调试环境和本地沙箱 |
| 读取远端最新业务上下文 | 返回 `remote_unavailable`；已有快照带来源、资源版本和获取时间 |
| 保存远端结构化业务结果 | 本地可保存草稿产物；业务写入等待新的有效授权与回执 |
| 远端用户请求 Agent | Gateway 展示离线，按协议拒绝或显式接纳有期限的排队请求 |

远端未连接不等于模型离线。文本历史读取独立于模型；聊天、压缩与总结需要对应模型连接可用。

远端 Tool 的结构、权限和实现注册与实时连接可用性分开。`integrations/<project-id>/` 保存已批准的 Extension、工具 schema 和适配，本地阶段即安装完整元数据，未配对时调用返回有界、结构化的不可用结果。模型在每次新调用的上下文中取得能力可用性说明，仍可选择本地工具。缺失本机必需 Extension 或定义快照属于装配错误，按 Core 预检阻止该 Harness 执行。

本地消息回复、会话派发、工作检查和纯本地交付由本机持久状态完成，按需要把进度同步给远端。普通对话及压缩的提示词从本地冻结定义装配，保持独立于远端输入入口和上下文读取。

历史总结使用指定会话或明确选中的本项目历史范围。只读 `read_history` 工具按分页和内容预算取实际 entries、摘要与产物引用，向模型提供可定位来源。角色已有工具也可由本地扩展映射到同一授权读取入口。单会话总结可直接使用 Pi 已加载历史，跨会话总结由管理服务按用户选定范围组装有界来源材料再提交给选定角色，工具权限保持原定义要求。跨项目访问需要单独授予作用域；读历史本身保持只读，只有用户发起总结才新增一次 Submission。

## 进程与生命周期

规划 CLI 为 `frogie daemon start|status|stop`，`frogie dashboard` 打开已有 daemon 的本地页面。Dashboard 需要启动服务时调用同一 daemon 启动入口；关闭页面只释放页面资源。常驻启动和平台自启动使用显式安装动作，开发命令保持与根 `AGENTS.md` 中的实际实现区分。

daemon 启动顺序：取得本地数据根独占权，加载项目与连接配置，启动本地管理接口，枚举绑定并完成只读预检，然后按保存的启用和恢复授权启动 Harness。单个绑定预检失败时，管理界面和其他项目继续可用。远端握手与本地启动分别进行。

Harness 工作进程按 [Core](03-core.md) 重建模型与 Registry，打开自己的 SQLite，提供只读快照，核对预算、取消、授权和投递回执后启用调度。观察操作保持只读；本机拥有者可按项目授权自动恢复，缺少条件时显示待处理原因。

| 操作 | 语义 |
| --- | --- |
| 关闭 Dashboard | 解除该页面订阅，daemon 和所有 Harness 继续运行 |
| 停用远端连接 | 关闭指定 Connector，本地工作继续，远端工具显示不可用 |
| 停止当前工作 | 按 Pi 所有权取消选定工作，等待实际终态 |
| 关闭 Harness | 停止接纳新输入并关闭存储，保留已提交状态和未完成工作的恢复依据 |
| 恢复 Harness | 对原绑定预检，重开原数据库，按保存的授权继续原工作 |
| 停止 daemon | 停止新请求，有界关闭连接及自有工作进程，保留本地状态 |

daemon 的本地管理接口和单个 Harness 启动默认期限各为 10 秒；远端连接使用独立期限。正常关闭先给予 5 秒优雅退出，再最多 5 秒清理自有进程。工作进程崩溃后显示故障及恢复入口，避免无界重启重复消耗模型预算。

定义卸载、项目移除与数据删除分为不同动作。移除登记先关闭对应 Harness 与 Connector；删除运行数据需要明确选择范围和确认，检查独占权与路径归属。活跃任务和未交付结果在确认前可见。

## 存储

```text
data/
  local/
    daemon.sqlite
    projects/<project-id>/
      connectors/<connector-id>/
        delivery.sqlite
      environments/<environment-id>/
        environment.json
        harnesses/<harness-id>/
          binding.json
          definition/
          session.sqlite
          artifacts/
          receipts/
          evals/<evaluation-id>/
  e2e/<run-id>/
    owner.json
    workspace/squads/
    daemon.sqlite
    projects/
    reports/
```

`daemon.sqlite` 保存本地项目登记、连接元数据和管理偏好；每个 `session.sqlite` 由 Pi 保存会话、Tasks、Submissions 与 Documents。`delivery.sqlite` 保存对应连接的待投递消息、去重关联、接收回执和持久业务操作状态。Pi 业务操作意图先提交，再由投递器按稳定操作 ID 建立 outbox；启动时扫描未结算意图，修复跨数据库提交窗口。

`binding.json` 与 Pi 绑定 Document 核对作用域、定义摘要和运行版本。冻结定义、产物与回执使用内容摘要，写入采用临时文件与原子落盘；未完成写入不会成为已确认引用。清理已完成投递数据时保留协议规定的去重凭据或墓碑。

模型和设备秘密放在本机私有配置目录，通过引用关联；数据根中的连接信息只保存非秘密元数据。备份在关闭对应存储或使用其安全备份能力时进行，SQLite、WAL 和 SHM 保持一致。恢复先核对版本与绑定；实现升级保持已有数据原样，转换或弃用另行确认。

Local 与 E2E 使用相同目录语义。E2E 的 daemon、Gateway、凭据、数据库和模型替身均由本次启动器创建，所有重置与清理验证 `owner.json` 及真实路径归属。seed 逻辑和输入留在 Git，生成结果进入 `data/`。

## 权限与执行隔离

本地管理接口绑定 loopback，使用一次性启动凭据、本地会话、Host／Origin 校验和写操作 CSRF。远端 Connector 只暴露协议中已授予的业务能力；管理定义、读取秘密和修改本地连接配置由本地管理接口承担。

本机用户在 Dashboard 管理模型连接、远端配对、权限收窄、凭据轮换和撤销。界面显示凭据标识、用途和失效原因；秘密只在必要的创建或输入阶段出现，正常查询、日志、错误和导出使用脱敏表示。

Harness 子进程是故障边界，Agent 脚本仍使用 [Dashboard](04-dashboard.md) 约定的 OS 沙箱。工具授权取角色、Workflow、本地项目授权与本次调用授权的交集。远端结构化内容按数据处理，代码扩展由本地用户显式安装并固定版本。

每个 Harness 具有自己的持久预算、截止点和活跃子工作上限；daemon 再限制全局模型与脚本并发，采用按 Harness 公平轮转的准入，避免单个项目占满全部执行槽。父会话等待子结果时释放模型并发槽。故障、等待与预算消耗在各项目概览中可定位。

## 观察与调试服务

本地管理服务提供项目目录与状态聚合，Core 提供实际 Harness、会话和任务投影。聚合返回各项自己的修订位置，跨 Harness 概览表达最近确认的事实，而非虚构一个全局原子快照。

用户可从全局进入项目、主控 Conversation、子会话和具体 Tool Task，查看请求来源、生效配置、模型输出、工具参数与回执、产物、压缩、错误和用量。能否操作由授权和实时能力决定；界面枚举以 SDK 契约为准。

Role 调试创建显式选择角色的新 Conversation，技能调试创建独立本地环境并展示输入输出及工具权限。脚本可以直接经过同一受控执行器验证契约；需要模型判断的 Skill 通过绑定该技能的角色执行。调试得到的产物与正式业务写回分别标识。

## 本地阶段验收

- 同一 daemon 同时托管两个不同项目的 Squad，主控、会话、SQLite、预算和产物分别隔离。
- 两个 Squad 同时取得真实模型答复，至少一组子会话有可观察的并行证据；一个项目停止或失败时另一个继续。
- Dashboard 可以管理定义和 Workflow、与主控或指定角色聊天、展开完整任务链、调试 Skill 并从产物追溯回执。
- 所有远端断开时，两组本地会话、历史读取和总结仍可用；远端上下文与业务保存明确显示不可用。
- 关闭浏览器保留执行；重启 daemon 后重开原数据库，恢复会话、待处理输入与压缩上下文。
- 项目与凭据管理通过真实本地接口验证；远端配对的完整握手留给通信阶段，界面按实际能力呈现。

验收分层见 [Tests](06-tests.md)、[Evals](07-evals.md)；交付门槛见 [MVP 实施](08-mvp-implementation.md)。
