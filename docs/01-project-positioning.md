# 01 - 项目定位

## 项目目的

Frogie 的目标是为多个业务项目提供统一的 Agent 设计台和公共接入能力。用户从一个中央入口定义、整理和理解各项目的 Agent，业务项目在本地加载这些定义并独立执行。

随着接入项目增多，角色配置、会话管理、工具接入和恢复逻辑容易形成多套实现。Frogie 将这些共性集中维护，让各项目使用一致的概念和基础机制，同时保留各自的业务规则与工作方式。

## 执行基础

Frogie 围绕 [Pi Durable](https://github.com/earendil-works/pi/tree/main/packages/durable) 构建，以它作为统一的 Agent 执行基础。设计和实现沿用 Pi 的概念与机制：Harness、会话（Conversation）、提交（Submission）、任务（Task）、扩展（Extension）和文档状态（Document）。

Frogie 将用户定义装配为 Pi 的配置和扩展，封装定义加载、会话管理、任务派发、结果交回与恢复接入。使用方可以继续通过 Pi 原生工具、扩展和钩子实现自己的业务能力。

## 定义设计台

用户在界面中组织各项目的 Agent 结构，查看角色职责、协作关系、模型选择和工具权限，并编辑以下内容：

| 内容 | 定义范围 |
| --- | --- |
| 角色（Role） | 职责、提示词、技能、模型、思考等级和允许使用的工具 |
| 技能（Skill） | 可复用的操作说明、脚本和相关资源 |
| 工作流（Workflow） | 工作步骤、角色分工、输入输出和交接要求 |
| 协作组（Squad） | 角色组合、主控安排和协作关系 |

同一角色可以创建多个会话实例。项目可以由模型主控动态安排工作，也可以由业务代码组织流程，或将两种方式结合使用。

设计结果保存为结构化 Markdown 文件，配套脚本保留为源文件。用户既可以通过界面整理，也可以直接阅读和编辑这些文件。

## 执行指导模式

| 模式 | 提供的内容 | 工作方式 |
| --- | --- | --- |
| 自由发挥 | 目标、角色职责、技能和可用工具 | Agent 自行安排完成方式 |
| 流程指导 | 工作步骤、分工，以及预期输入、输出和交接要求 | Agent 根据流程说明开展工作 |

流程指导通过 Markdown 向 Agent 描述预期做法，具体执行保留模型自主性。输入输出约定和工作材料也可以采用 Markdown。工具权限、资源访问和业务审批由运行端代码执行约束。

## 职责划分

| 归属 | 职责 |
| --- | --- |
| Frogie 设计台 | 定义、组合和整理角色、技能、协作组与工作流，提供跨项目的统一视图 |
| Frogie 公共接入能力 | 加载定义，封装 Pi Durable 的运行接入和公共机制，供业务项目使用 |
| Pi Durable | 提供持久化执行、会话、任务、工具调用和恢复机制 |
| 使用方项目 | 实现业务工具、认证、触发入口、输入输出、界面交互和业务规则 |
| 项目本地运行端 | 承载执行进程、沙箱、SQLite 状态和工作产物 |

使用方主要围绕业务编写工具和接入逻辑，公共运行机制由 Frogie 统一维护。工具实现由使用方提供或注册，实际权限由角色定义和项目授权共同限定。

## 本地运行

Agent 在本机运行，通过认证连接其服务的业务项目，使用本地文件、工具、算力和执行环境。

Agent 调用的脚本和项目代码通过本地沙箱执行。业务 API 由受控工具接入，检查对应账号、资源和操作权限。模型连接、业务凭据和机器配置由各项目的本地运行端管理。

公共接入代码随使用方运行。各项目独立管理自己的进程和状态，设计界面关闭后仍可继续工作和恢复执行。

## 定义与运行数据

设计台维护角色、技能、工作流和协作组的定义。定义存放在用户管理的工作区，按版本供项目选用。

运行时使用的会话、任务进度、SQLite 数据、结果和回执由使用方项目持有。执行恢复基于项目保存的状态、所用定义版本及对应工具实现。凭据保存在本机私有配置中。

中央入口帮助用户理解各项目如何组成、具备哪些能力；各项目负责实际业务的执行和交付。

## 项目价值

接入第二十个项目时，用户仍使用同一套概念理解 Agent，开发者仍使用同一套公共运行机制，并能实现前十九个项目都没有的新业务。
