# 01 - 项目定位

## 项目目的

Frogie 的定位是个人各项目的 AI 核心管理平台，基于 [Pi Durable](https://github.com/earendil-works/pi/tree/main/packages/durable) 构建，集中管理已接入项目的 Agent 定义，提供角色、技能和工作流的编排设计服务。

使用方项目通过统一协议使用这些定义，实现自己的界面、业务工具和输入输出，在本地承载执行过程与运行数据。Frogie 提供共同的概念、接入能力和权限机制，各项目保留自己的业务形式。

## 框架基础

Pi Durable 是统一的执行基础。Frogie 的定义和接入约定沿用 Pi 的会话（Conversation）、提交（Submission）、任务（Task）、扩展（Extension）和文档状态（Document）等概念。

公共能力围绕 Pi 提供的机制封装，业务扩展通过 Pi 原生的工具、扩展和钩子接入。

## 主要模块

### 项目与 Agent 定义管理

保存已接入项目的定义，让用户统一整理各项目的 Agent 类型、职责与组成。

| 内容 | 定义范围 |
| --- | --- |
| Agent | 服务目标、角色组成和能力配置 |
| 角色（Role） | 职责、提示词、模型、思考等级、所用技能和工具权限 |
| 技能（Skill） | 可复用的操作说明、脚本和相关资源 |
| 工作流（Workflow） | 工作步骤、角色分工、输入输出和交接约定 |
| 协作组（Squad） | 角色组合、主控安排和协作关系 |

定义以结构化 Markdown 和配套脚本组织，供使用方项目读取和使用。同一角色可以用于多个会话实例。

### 工作流与技能编排

用户组合角色、提示词和技能，安排主控、分工和交接方式。执行可以采用自由发挥或流程指导：前者由 Agent 根据目标安排工作，后者通过 Markdown 提供步骤与输入输出说明，具体执行保留模型自主性。

工作流在 Frogie 中完成设计，使用方在具体运行环境中应用，并在授权范围内调整配置与业务接入。

### 统一接入协议与扩展

提供与 Pi Durable 概念一致的接入约定，统一定义使用、会话交互、输入输出传递、工具接入和扩展注册。公共接入能力按约定装配和校验配置，使各项目在共同规则内扩展。

使用方可以实现自己的 Extension、工具和业务处理，通过统一机制接入。公共协议负责接入的一致性，业务实现负责具体行为。

### 界面集成能力

为使用方提供统一的交互基础能力和可选模板，支持聊天、提示词编辑、技能读取与编辑等场景。

各项目可以实现自己的 Chat UI 和定义编辑界面，沿用各自网站的布局与视觉风格。界面通过公共机制使用定义、提交输入、接收事件和结果，保持一致的交互语义。

### 权限管理

提供统一的权限定义和检查机制，管理角色、工作流可使用的工具、扩展及资源范围。用户在设计时配置能力边界，在具体环境中按授权进行使用和微调。

运行端结合项目认证与实际授权执行检查，业务工具负责相应的资源和操作权限。Agent 调用的脚本与项目代码通过本地沙箱执行。

### 本地 Dashboard

Dashboard 限定在本机运行和访问，通过 CLI 启动，并通过本地 URL 打开。

用户可以查看已接入哪些项目、有多少种 Agent、每个工作流的内容、角色职责及相互关系，并在界面中整理定义和进行编排。Dashboard 是理解和设计各项目 AI 能力的中央入口。

## 职责与数据归属

| 归属 | 职责与数据 |
| --- | --- |
| Frogie | 保存接入项目的 Agent、角色、提示词、技能和工作流定义；提供编排设计、统一协议、权限机制、界面基础能力和本地 Dashboard |
| Pi Durable | 提供会话、任务、工具调用、持久化状态与恢复的基础机制 |
| 使用方项目 | 实现自己的 UI、认证、触发入口、输入输出工具、扩展和业务规则；按公共协议使用定义 |
| 使用方本地运行端 | 实现运行存储与恢复接入，持有 SQLite、会话历史、恢复数据和执行产物，管理本地沙箱与凭据 |

定义由 Frogie 集中维护，具体执行及其数据由使用方项目管理。公共代码随使用方运行，各项目在 Dashboard 关闭后仍可独立执行和恢复。

## 项目价值

用户通过一个平台理解和设计个人各项目的 AI 能力。开发者沿用统一的定义、协议和基础机制，在各自网站和本地环境中实现业务，随着项目数量增长持续复用公共能力。
