# 01 - 项目定位

## 项目目的

Frogie 的定位是个人多 Agent 管理平台，基于 [Pi Durable](https://github.com/earendil-works/pi/tree/main/packages/durable) 构建。项目以 Squad 组织 Markdown 角色定义、技能和工作流，通过本地 Dashboard 提供编排、管理、调试和观察能力。

Frogie 负责定义层的统一管理，以及运行接入和持久化协议。各集成项目使用公共接入代码创建并托管 Pi Harness，加载对应 Squad，承载自己的业务执行、界面和运行数据。Frogie 的本地调试端首先实现同一套协议，服务于自身调试，也作为项目集成的参考实现。

## 设计原则

- **沿用 Pi 概念**：执行、持久化和扩展建立在 Pi Durable 原生机制上，公共协议与其语义保持一致。
- **MD 承载定义**：Markdown 文件与嵌套目录构成定义骨架，组合提示词、Skills 和 Scripts，表达主控、子角色及其协作关系。
- **Git 记录演变**：定义和配套脚本纳入仓库版本管理，通过提交与差异查看变更历史。
- **执行归属使用方**：集成项目管理自身的 Harness、存储、恢复和业务行为，按统一协议接入。
- **自身先行验证**：本地调试端和集成项目采用相同协议，通过测试与 Evaluation 验证公共能力。

## 术语与层次

本节是后续文档、界面和接入协议的统一术语依据。Frogie 定义层负责描述协作结构，Pi 运行层负责承载会话与执行，两层通过角色配置装配和 Squad 绑定关联。

### 定义层

以下是 Frogie 的定义组织约定，以 Squad 描述一组角色、能力和协作方式。初期采用一个项目配置一个 Squad 的组织方式。

| 概念 | 含义 |
| --- | --- |
| 项目（Project） | Frogie 中的管理单位，对应一个接入的业务项目，管理其 Squad 定义和运行环境绑定 |
| 协作组（Squad） | Frogie 的协作定义单元，组合角色、技能、工作流和能力配置，可装配到一个 Harness |
| 角色（Role） | 可复用的 Agent 配置定义，包含职责、提示词、模型、思考等级、技能和工具要求 |
| 提示词（Prompt） | 角色职责、行为要求和任务指导等文本，装配为 Pi 的指令或提示词片段 |
| 技能（Skill） | 角色可使用的操作说明、脚本和相关资源 |
| 脚本（Script） | 与定义配套的可执行源文件，通过运行端授权的工具和执行环境调用 |
| 工作流（Workflow） | 面向模型的工作步骤、角色分工、输入输出和交接说明 |

Squad 内的角色定义以 MD 为依据，嵌套目录与文件内容共同表达主控角色、子角色及其归属。技能和工作流通过引用参与组合。Dashboard 的管理和编辑操作作用于这套文件。

主控角色负责接收目标、协调分工和汇总结果；子角色承担派发给它的职责。“主 Agent／子 Agent”在定义层分别对应主控角色／子角色，在运行层分别对应应用这些角色配置的主控会话／子会话。

### Pi 运行层

运行层采用 Pi Durable 的原始概念，由集成项目或本地调试端承载。

| 概念 | Pi 中的含义 |
| --- | --- |
| Harness | 一份已打开的存储及其执行机制，管理其中的会话、任务和状态提交 |
| Conversation | 具有独立身份的对话记录，关联 Agent 配置、历史和运行状态 |
| Agent | 某个 Conversation 执行时使用的模型、思考等级、指令、工具、扩展和工作目录配置，按会话保存配置选择并在使用时解析 |
| Submission | 向 Conversation 提交的一份输入或被动写入 |
| Turn | 一次模型响应及其发起的工具调用，称为一轮交互 |
| Run | Conversation 处理输入的一段执行过程，可包含多轮模型与工具交互 |
| Task | 保存执行阶段与检查点的持久化状态机，归属会话或其他任务，驱动模型生成和工具调用等工作 |
| Tool | 向模型开放的可调用能力，包含参数定义和执行实现，由运行端执行 |
| Extension | 包含工具、提示词片段、钩子、包装器或任务等能力的具名扩展 |
| Registry | 当前进程安装扩展的注册表，用于将保存的扩展和工具名称解析为具体实现 |
| Document（状态文档） | Pi 中按提交保存的结构化状态，用于记录 Agent 配置、队列、用量或应用状态 |

后续文档用“角色定义”指 MD 中可复用的配置，用“Agent 配置”指 Pi 会话使用的配置，用“会话实例”指具有具体身份和历史的 Conversation。Markdown 文档属于定义源文件，Pi Document 属于运行状态。

### 运行承载与界面

| 概念 | 含义 |
| --- | --- |
| 运行环境 | 一套独立的运行配置、授权和存储范围，例如业务环境或本地调试环境 |
| 运行端 | 创建并托管 Harness 的宿主程序，负责连接模型、工具、存储及业务输入输出 |
| 本地调试端 | Frogie 提供的运行端参考实现，使用同一接入协议加载 Squad 并执行调试 |
| Dashboard | Frogie 的本地管理与观察界面，通过公共机制编辑定义、连接运行端和发起调试 |

### Squad 与 Harness 的映射

Squad 是定义单元，Harness 是 Pi 运行承载单元。Frogie 规定：同一运行环境内，一个 Squad 对应一个 Harness，一个 Harness 承载一个 Squad。

同一份 Squad 定义可以分别用于本地调试环境和业务环境。每个环境创建自己的 Harness，独立管理存储、会话和任务。

```text
定义层：项目 -> Squad
                 -> 主控角色 / 子角色（MD）
                 -> Skills / Scripts / Workflows

绑定：同一运行环境内 Squad <-> Harness

运行层：Harness -> Conversation（可创建多个）
                      -> Agent 配置（由角色定义装配）
                      -> 历史和关联状态
                      -> Submission 输入或写入
                      -> Run 执行过程，由 Task 驱动
```

Harness 内各 Conversation 的 Agent 配置由 Squad 中相应的角色定义装配。同一角色可以用于多个 Conversation，每个 Conversation 持有自己的 Agent 配置和历史。目录描述设计上的主从结构，运行时通过 Pi 的任务所有权落实子会话的派发、等待和取消关系。

Submission 按 Pi 规则进入会话：普通输入启动或排队等待执行，插话加入当前 Run，被动写入追加记录。Run 可以包含多个 Turn，模型生成和工具调用通过 Task 执行。

## 主要模块

### 定义管理与编排

集中管理已接入项目的 Squad 及其角色目录、MD 文件、技能和脚本。用户在 Squad 中组合角色、提示词和技能，设计工作流，配置模型、思考等级与能力范围。

执行指导分为自由发挥和流程指导。自由发挥由 Agent 根据目标安排工作；流程指导通过 Markdown 提供步骤和输入输出要求，具体执行保留模型自主性。集成项目也可以用业务代码组织流程，调用相同的公共能力。

### 定义解析与校验

统一读取 Squad 的 MD 目录，识别角色层级，解析技能、脚本和工作流引用，校验定义完整性、引用有效性及运行端所需能力。

解析结果用于装配 Pi 的 Agent 配置和扩展。Dashboard、集成项目和本地调试端共用这一机制，使文件内容、界面呈现和运行配置保持一致。

### 定义版本与项目绑定

通过 Git 管理定义和脚本的已提交历史，记录项目选用的 Squad 及其定义版本，并将各环境的 Harness、会话与所用版本关联。

中央编辑与项目侧微调都通过统一机制明确修改范围、保存位置和生效版本，区分共享定义与项目配置。

### 运行与持久化协议

基于 Pi 的存储、提交和任务机制，定义统一的接入与持久化约定，涵盖 Squad 与 Harness 的绑定、会话身份、定义版本、输入投递、结果交回、取消和恢复行为。

各集成项目参考本地调试端的接入方式，复用 Frogie 公共代码创建并托管 Pi Harness，提供存储、模型连接、执行环境和业务扩展，管理启动、关闭与恢复。Frogie 统一维护定义装配、协议校验和公共运行接入；本地调试端遵守同一套要求。

### 扩展与界面集成

使用方通过 Pi 原生工具、Extension 和钩子实现业务能力，自定义输入、输出、触发入口和业务处理，再通过公共协议接入。

Frogie 提供统一交互能力和可选模板，支持 Chat UI、提示词编辑、技能读取与编辑。各项目沿用自己的布局和视觉风格，通过相同机制提交输入、接收事件和结果。

### 权限管理

统一描述角色和工作流可使用的工具、扩展及资源范围。定义编辑与运行配置的微调按授权进行，实际执行权限由定义和项目授权共同限定。

运行端执行权限检查，业务工具约束对应账号、资源和操作。Agent 调用的脚本与项目代码通过本地沙箱执行，凭据由各运行环境管理。

### 统一运行观察与诊断

基于 Pi 的状态与观察接口，统一提供会话和任务状态、模型输出、工具调用与结果、错误、取消和恢复情况，以及基础用量信息。

Dashboard、使用方 UI、调试和 Evaluation 共用这些信息。定义结构、实际加载配置和当前执行情况分别展示，运行信息从对应运行端取得。

### 本地 Dashboard 与调试端

Dashboard 限定在本机运行和访问，通过 CLI 启动，并通过本地 URL 打开。它提供两个入口：

- **管理**：查看项目、Squad、角色目录、技能和工作流，以用户友好的界面完成基于 MD 的编辑和编排。
- **观察与调试**：通过授权连接运行端，查看 Squad 对应的 Harness、已加载定义、会话、任务和诊断信息，使用本地调试端试运行 Squad。

本地调试端为选定 Squad 创建独立 Harness，提供存储、恢复和观察协议的示例实现，首先验证 Frogie 自己的定义与公共能力，同时供集成项目参考。调试运行数据保存在独立本地目录。

### Evaluation

用评估用例描述预期行为，通过测试驱动公共能力开发，并验证角色、技能和工作流定义的效果。基础机制测试和 Agent 行为评估分别组织，评估结果关联所用定义版本。

质量验证按 6DQ 分层，首期落实 L1：有意义的单元测试，语句、分支、函数、行四项覆盖率各达到 95%，严格类型检查与 lint／格式检查均为零错误、零警告，以及针对 Git 暂存快照的提交前自动检查和失败拦截。

基础测试使用模拟模型、工具和独立测试数据。验证范围从定义解析、配置校验和权限检查起步，逐步覆盖协议符合性、持久化恢复和 Agent 行为。后续按 6DQ 补充 L2 接口集成、L3 完整流程、G2 安全检查和 D1 测试隔离的验证。

## 职责与数据归属

| 归属 | 职责与数据 |
| --- | --- |
| Frogie 定义层 | 保存并版本管理 Squad、MD 目录、角色、提示词、技能、脚本和工作流，通过统一机制解析、校验和编辑 |
| Frogie 公共能力 | 定义运行与持久化协议，提供权限、扩展接入、界面集成、观察诊断和 Evaluation 能力 |
| Frogie Dashboard 与调试端 | 提供管理和观察界面，承载本地调试 Harness 参考实现及其独立运行数据 |
| Pi Durable | 提供会话、任务、工具调用、持久化状态与恢复的基础机制 |
| 集成项目 | 复用公共接入代码托管 Squad 对应的 Pi Harness，提供业务 UI、认证、输入输出工具和扩展，按统一协议接入运行与持久化 |
| 各运行环境 | 分别持有 SQLite、会话历史、恢复数据、执行与评估产物，管理本地沙箱和凭据 |

定义与脚本随仓库记录历史，业务执行数据由集成项目保存，本地调试数据由调试端保存。Dashboard 通过协议管理和观察，各项目独立运行与恢复。

## 项目价值

用户通过一套 MD 定义和本地界面管理个人各项目的多 Agent 体系。开发者沿用 Pi 的概念、公共协议和参考实现，在自己的项目中扩展业务，并通过统一的观察与评估机制验证结果。
