# 01 - 项目定位

## 项目目的

Frogie 是基于 [Pi Durable](https://github.com/earendil-works/pi/tree/main/packages/durable) 的个人多 Agent 管理平台。私有仓库以 Markdown、Skills 和 Scripts 管理各项目的 Squad；本机常驻 daemon 统一执行这些 Squad，通过 Dashboard 提供设计、聊天、调试和全局观察。

每个项目的主控会话、子角色会话、执行历史、SQLite 与恢复数据都由本机 Frogie 管理。业务项目保留自己的界面、用户认证、业务规则和最终产物，通过公开通信 SDK 接入本机能力。SDK 交付协议与客户端，私有角色定义和执行实现留在 Frogie。

本文及相关模块文档描述目标架构，已有实现与分阶段交付边界见 [MVP 实施](08-mvp-implementation.md)。

## 设计原则

- **沿用 Pi 概念**：执行、持久化和扩展建立在 Pi Durable 原生机制上，公共协议与其语义保持一致。
- **MD 承载定义**：Markdown 文件与嵌套目录构成定义骨架，组合提示词、Skills 和 Scripts，表达主控、子角色及其协作关系。
- **Git 记录演变**：定义和配套脚本纳入仓库版本管理，通过提交与差异查看变更历史。
- **本地统一执行**：daemon 托管各项目的 Harness、模型连接、沙箱、存储和恢复，Dashboard 是它的本地管理入口。
- **两端独立闭环**：Frogie 可以独立聊天、读取历史、总结与调试；业务项目可以独立提供已有业务功能。连接提供实时上下文、远程 Agent 调用和业务结果写回。
- **业务保持独立**：项目自己的认证、审批、资源版本与产物存储决定业务操作是否成立。
- **自身先行验证**：先完成本机至少两个独立 Squad 的完整闭环，再验证通信 SDK 和不同项目的业务集成。

## 术语与层次

本节是后续文档、界面和接入协议的统一术语依据。Frogie 定义层负责描述协作结构，Pi 运行层负责承载会话与执行，两层通过角色配置装配和 Squad 绑定关联。

### 定义层

以下是 Frogie 的定义组织约定，以 Squad 描述一组角色、能力和协作方式。初期采用一个项目配置一个 Squad 的组织方式。

| 概念 | 含义 |
| --- | --- |
| 项目（Project） | Frogie 中的管理单位，登记其 Squad、运行环境、模型与权限，以及可选的远端连接；纯本地项目同样成立 |
| 协作组（Squad） | Frogie 的协作定义单元，组合角色、技能、工作流和能力配置，可装配到一个 Harness |
| 角色（Role） | 可复用的 Agent 配置定义，包含职责、提示词、模型、思考等级、技能和工具要求 |
| 提示词（Prompt） | 角色职责、行为要求和任务指导等文本，装配为 Pi 的指令或提示词片段 |
| 技能（Skill） | 角色可使用的操作说明、脚本和相关资源 |
| 脚本（Script） | 与定义配套的可执行源文件，通过运行端授权的工具和执行环境调用 |
| 工作流（Workflow） | 面向模型的工作步骤、角色分工、输入输出和交接说明，以 MD 保存步骤图和正文 |

Squad 内的角色定义以 MD 为依据，嵌套目录与文件内容共同表达主控角色、子角色及其归属。技能和工作流通过引用参与组合。Dashboard 的管理和编辑操作作用于这套文件。

主控角色负责接收目标、协调分工和汇总结果；子角色承担派发给它的职责。“主 Agent／子 Agent”在定义层分别对应主控角色／子角色，在运行层分别对应应用这些角色配置的主控会话／子会话。

### Pi 运行层

运行层采用 Pi Durable 的原始概念，由 Frogie daemon 托管。daemon 是应用宿主，不是新增的一层 Pi Agent。

| 概念 | Pi 中的含义 |
| --- | --- |
| Harness | 一份已打开的存储及其执行机制，管理其中的会话、任务和状态提交 |
| Conversation | 具有独立身份的对话记录，关联 Agent 配置、历史和运行状态 |
| Agent | 某个 Conversation 执行时使用的模型、思考等级、指令、工具、扩展和工作目录配置，按会话保存配置选择并在使用时解析 |
| Submission | 向 Conversation 提交的一份输入或被动写入 |
| Turn | 一次模型响应及其发起的工具调用，称为一轮交互 |
| Run | Conversation 处理输入的一段执行过程，可包含多轮模型与工具交互 |
| Task | 保存执行阶段与检查点的持久化状态机，归属会话或其他任务，驱动模型生成和工具调用等工作 |
| Tool | 向模型开放的可调用能力，包含参数定义和执行实现，由运行端执行 |
| Extension | 包含工具、提示词片段、钩子、包装器或任务等能力的具名扩展 |
| Registry | 当前进程安装扩展的注册表，用于将保存的扩展和工具名称解析为具体实现 |
| Document（状态文档） | Pi 中按提交保存的结构化状态，用于记录 Agent 配置、队列、用量或应用状态 |

后续文档用“角色定义”指 MD 中可复用的配置，用“Agent 配置”指 Pi 会话使用的配置，用“会话实例”指具有具体身份和历史的 Conversation。Markdown 文档属于定义源文件，Pi Document 属于运行状态。

### 运行承载与界面

| 概念 | 含义 |
| --- | --- |
| 运行环境 | 一套独立的运行配置、授权和本地存储范围，具有稳定的 `environmentId` |
| Daemon | Frogie 的本机常驻宿主，管理项目、Harness 工作进程、本地管理服务及出站连接 |
| Harness 工作进程 | daemon 托管的一份 Harness 执行进程，独占对应 SQLite；进程是故障隔离单元，OS 沙箱另行约束脚本 |
| Dashboard | daemon 的本地管理与观察客户端，编辑定义、管理项目与凭据、聊天和调试 |
| 远端连接（Connector） | 本机主动建立的、绑定项目和远端环境的认证 WSS 通道，承载请求、观察和业务工具调用 |
| 项目接入端（Gateway） | 集成项目中的 SDK 服务端适配，完成用户授权、设备配对、可靠投递及业务工具处理 |
| 通信 SDK | 无私有定义和 Pi 运行依赖的公开 npm 包，提供协议、客户端、接入适配与符合性测试 |

Dashboard 按 Local、E2E 区分日常使用与隔离验证，两者的数据库均保存在本机。远端的环境标识属于项目连接配置，和本机模式分别绑定。例如 Local 可以连接获准的云端业务环境，自动 E2E 只连接本次测试的替身服务。

### Squad 与 Harness 的映射

Squad 是定义单元，Harness 是 Pi 运行承载单元。Frogie 规定：同一运行环境内，一个 Squad 对应一个 Harness，一个 Harness 承载一个 Squad。

同一份 Squad 定义可以用于不同本地环境。每个环境创建自己的 Harness，独立管理存储、会话和任务。SQLite 按项目、环境和 Harness 隔离；角色在同一 Harness 内创建多个 Conversation。

```text
定义层：项目 -> Squad
                 -> 主控角色 / 子角色（MD）
                 -> Skills / Scripts / Workflows

绑定：同一运行环境内 Squad <-> Harness

运行承载：Daemon -> 项目 / 环境 -> Harness

Pi 运行层：Harness -> Conversation（可创建多个）
                      -> Agent 配置（由角色定义装配）
                      -> 历史和关联状态
                      -> Submission 输入或写入
                      -> Run 执行过程，由 Task 驱动
```

Harness 内各 Conversation 的 Agent 配置由 Squad 中相应的角色定义装配。同一角色可以用于多个 Conversation，每个 Conversation 持有自己的 Agent 配置和历史。目录描述设计上的主从结构，运行时通过 Pi 的任务所有权落实子会话的派发、等待和取消关系。

Submission 按 Pi 规则进入会话：普通输入启动或排队等待执行，插话加入当前 Run，被动写入追加记录。Run 可以包含多个 Turn，模型生成和工具调用通过 Task 执行。

## 主要模块

### 定义管理与编排

集中管理已接入项目的 Squad 及其角色目录、MD 文件、技能和脚本。用户在 Squad 中组合角色、提示词和技能，设计工作流，配置模型、思考等级与能力范围。

Workflow 支持在可视化画布中拖入角色步骤、连线并打开角色与技能编辑。画布与源码编辑作用于同一份 MD；角色目录表达派发归属，步骤图表达工作指导，Pi 的任务图表达实际执行。

执行指导分为自由发挥和流程指导。自由发挥由 Agent 根据目标安排工作；流程指导通过 Markdown 提供步骤和输入输出要求，具体执行保留模型自主性。集成项目也可以用业务代码组织流程，调用相同的公共能力。

### 定义解析与校验

统一读取 Squad 的 MD 目录，识别角色层级，解析技能、脚本和工作流引用，校验定义完整性、引用有效性及运行端所需能力。

解析结果由 daemon 用于装配 Pi 的 Agent 配置和扩展。Dashboard 编辑同一份文件，集成项目通过 SDK 获取获准的结构说明和执行投影。

### 定义版本与项目绑定

通过 Git 管理定义和脚本的已提交历史，记录项目选用的 Squad 及其定义版本，并将各环境的 Harness、会话与所用版本关联。

角色、提示词与技能的编辑通过本地管理服务完成。环境微调明确修改范围和生效版本；业务项目的栏目设置、作品资料等通过上下文接口按资源版本读取。

### 本地执行与持久化

基于 Pi 的存储、提交和任务机制，定义统一的接入与持久化约定，涵盖 Squad 与 Harness 的绑定、会话身份、定义版本、输入投递、结果交回、取消和恢复行为。

daemon 为每个绑定管理独立工作进程、SQLite、冻结定义、用量预算和产物引用。会话、任务与压缩使用 Pi 原生机制；项目目录、连接登记和投递回执由 Frogie 管理。浏览器关闭和远端断线只影响观察或远端能力，已经接纳的本地工作继续遵循自身授权与预算。

### 双向通信与业务接入

Frogie 主动向各项目的 Gateway 建立出站 WSS，使用固定远端地址、设备配对和项目级授权。云端通过已建立的连接提交工作，本机通过同一连接读取业务上下文、发送进度、调用业务工具和取得保存回执。通信协议详见 [通信 SDK](11-communication-sdk.md)。

两端分别保存必要的投递记录，通过稳定请求 ID、幂等操作、版本检查和断线重同步处理网络中断。业务数据库保存最终作品与操作回执，Agent 的恢复依据始终在本机。

### 扩展与界面集成

本机扩展通过 Pi Tool、Extension 与钩子接入执行。集成项目通过 SDK 注册具有输入输出结构、权限和回执的业务能力，Frogie 将获准能力装配为 Agent 可调用的工具；项目侧使用普通业务处理器。

SDK 提供会话历史、提交、任务图、工具进展、压缩、产物、用量和连接状态等高级接口。Dashboard 从通用 Agent 视角呈现，集成项目从业务视角呈现相同的授权投影，沿用自己的布局与视觉风格。

### 权限管理

统一描述角色和工作流可使用的工具、扩展及资源范围。定义编辑与运行配置的微调按授权进行，实际执行权限由定义和项目授权共同限定。

daemon 执行本地权限检查，Gateway 执行用户、资源和业务操作授权。设备配对只授予明确的项目与能力范围，角色权限和调用者权限分别校验。脚本通过本地 OS 沙箱执行；模型与设备凭据保存在本机私有配置，Dashboard 提供受控管理界面。

### 统一运行观察与诊断

基于 Pi 的状态与观察接口，统一提供会话和任务状态、模型输出、工具调用与结果、错误、取消和恢复情况，以及基础用量信息。

Dashboard、使用方 UI、调试和 Evaluation 共用这些信息。全局概览汇总哪些 Squad 正在工作、哪些会话活跃、当前工具或等待原因，再逐层进入角色、Submission 和 Task。远端连接状态、Pi 执行状态和业务交付状态分别展示；进度以实际事件与回执为依据。

### 本地 Dashboard 与调试

Dashboard 限定在本机运行和访问，通过 CLI 启动，并通过本地 URL 打开。侧栏顶部按工作区方式切换 Squad、对应 Harness 和运行环境，导航与内容围绕当前选择展开。它提供两个入口：

- **管理**：查看项目、Squad、角色目录、技能和工作流，以用户友好的界面完成基于 MD 的编辑和编排。
- **观察与调试**：查看各项目的 Harness、主控与子会话、任务和诊断，直接与选定角色聊天、测试 Skill、读取和总结本地历史，管理远端配对与能力授权。

调试使用 daemon 的正式执行路径，并为需要隔离的测试建立独立环境。本机各模式的 SQLite、历史和执行产物位于 Git 忽略的 `data/`；初始化材料与 seed 生成源码由 Git 管理。管理接口仅在本机访问，daemon 生命周期独立于 Dashboard 页面。

### 两端独立使用

远端未连接时，业务项目继续提供自己的内容、编辑、审批和播放等功能；Agent 入口展示离线及其最后确认的信息。Frogie 继续使用本地模型连接、会话历史和产物完成聊天、总结与调试。这里的离线指与业务项目断开，模型提供方的可用性另行检查。

需要远端最新上下文或保存结构化业务结果的动作显示当前不可用。已有上下文快照标明来源和版本，本地产物可以先保存；后续业务写回经过重新授权、资源版本检查与回执确认。

### Evaluation

用评估用例描述预期行为，通过测试驱动公共能力开发，并验证角色、技能和工作流定义的效果。基础机制测试和 Agent 行为评估分别组织，评估结果关联所用定义版本。

质量验证按 6DQ 分层，首期落实 L1：有意义的单元测试，语句、分支、函数、行四项覆盖率各达到 95%，严格类型检查与 lint／格式检查均为零错误、零警告，以及针对 Git 暂存快照的提交前自动检查和失败拦截。

基础测试使用模拟模型、工具和独立测试数据。MVP 同时通过关键 L2 接入与恢复检查、从空工作区搭建完整 Squad 的 L3 E2E，以及真实模型评估验证可用路径。D1 隔离贯穿各层，G2 安全检查随相关边界和门禁建设逐步落实。

## 职责与数据归属

| 归属 | 职责与数据 |
| --- | --- |
| Frogie 定义层 | 保存并版本管理 Squad、MD 目录、角色、提示词、技能、脚本和工作流，通过统一机制解析、校验和编辑 |
| Frogie Core 与 daemon | 装配 Pi、托管各项目 Harness，保存本地 SQLite、历史、检查点、上下文快照与产物，管理沙箱、模型和连接 |
| Frogie Dashboard | 提供全局项目管理、定义设计、认证管理、聊天、执行观察、调试与 Evaluation 界面 |
| 公共通信 SDK | 定义认证、消息、数据投影、查询订阅、工具回执和符合性测试，供本地与业务 UI 复用 |
| Pi Durable | 提供会话、任务、工具调用、持久化状态与恢复的基础机制 |
| 集成项目 | 保存业务资料与最终作品，提供自己的 UI、用户认证、审批、上下文与业务工具处理器，以及必要的投递和操作回执 |

私有定义与脚本随仓库记录历史；本机运行数据随对应 Harness 持久保存；最终业务数据在项目内提交。远端可保留有期限的展示缓存，历史查询与执行恢复的权威来源仍是本机。

## 项目价值

用户通过一个本机入口理解和管理个人各项目的 Agent 全景。Frogie 集中维护 Pi、定义、执行和恢复；各业务项目复用通信能力，专注自己的工具、界面和成果，接入更多项目时继续遵循同一套可测试契约。
